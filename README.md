# 🛠️ AmneziaWG WARP Config Generator

ابزار تحت وب و بدون سرور برای ساخت کانفیگ **AmneziaWG** با استفاده از **Cloudflare WARP**.
کل برنامه یک فایل `index.html` است و کلیدها در مرورگر خودتان ساخته می‌شوند.

👉 **[ورود به برنامه (Live Demo)](https://amiralidlb93-hash.github.io/-AmneziaWG-Config-Generator/)**

---

## ✨ قابلیت‌ها

- ثبت خودکار یک دستگاه WARP تازه و دریافت آدرس و کلید عمومی سرور
- ساخت جفت‌کلید WireGuard داخل مرورگر (کلید خصوصی هیچ‌جا ارسال نمی‌شود)
- حالت‌های پکت زباله (Junk): **سبک**، **سنگین** و **دلخواه** (`Jc`، `Jmin`، `Jmax`)
- پشتیبانی از پارامترهای **Amnezia 1.5** (`I1` تا `I5`)
- تنظیم MTU (پیش‌فرض `1280`)
- دکمه‌ی «آی‌پی تصادفی» برای انتخاب endpoint از رنج‌های WARP
- کپی یا دانلود فایل `.conf`
- رابط فارسی و راست‌چین، سازگار با حالت تاریک و موبایل

## 🚀 نحوه‌ی استفاده

1. صفحه‌ی برنامه را باز کنید.
2. (اختیاری) endpoint را وارد کنید یا «آی‌پی تصادفی» را بزنید. خالی بماند، آدرس پیش‌فرض WARP استفاده می‌شود.
3. حالت Junk و MTU را انتخاب کنید.
4. اگر کلاینت شما Amnezia 1.5 را پشتیبانی می‌کند، تیک آن را بزنید.
5. روی **ساخت کانفیگ** بزنید.
6. کانفیگ را کپی یا دانلود کنید.

### افزودن کانفیگ به AmneziaVPN

1. اپ **AmneziaVPN** را باز کنید و دکمه‌ی **+** را بزنید.
2. اگر کپی کرده‌اید: **Insert** را بزنید و متن را جایگذاری کنید.
3. اگر دانلود کرده‌اید: **File with connection settings** را بزنید و فایل `.conf` را انتخاب کنید.
4. اتصال را فعال کنید.

## ☁️ ساخت پروکسی با Cloudflare Worker (در صورت خطای CORS)

### Worker چیست و چرا لازم است؟

مرورگر به‌دلیل سیاست امنیتی CORS اجازه نمی‌دهد صفحه‌ی ما مستقیم به `api.cloudflareclient.com` درخواست بفرستد. Worker یک واسطه‌ی کوچک و رایگان روی زیرساخت Cloudflare است که:

- درخواست ثبت دستگاه را از صفحه می‌گیرد،
- هدرهای لازم (`User-Agent` و `CF-Client-Version`) را اضافه می‌کند و به API می‌فرستد،
- جواب را با هدرهای CORS به صفحه برمی‌گرداند.

Worker هیچ داده‌ای ذخیره نمی‌کند و کلید خصوصی را هرگز نمی‌بیند.

### مراحل ساخت

1. در [dash.cloudflare.com](https://dash.cloudflare.com) ثبت‌نام کنید یا وارد شوید (حساب رایگان کافی است).
2. از منوی کناری **Workers & Pages** را باز کنید و **Create** → **Create Worker** را بزنید.
3. یک اسم دلخواه بدهید (مثلاً `warp-proxy`) و **Deploy** را بزنید.
4. بعد از ساخته شدن، **Edit code** را بزنید.
5. همه‌ی کد پیش‌فرض را پاک کنید و کد پایین را جایگزین کنید.
6. **Deploy** را بزنید.
7. آدرس Worker را کپی کنید. شکلش این است: `https://warp-proxy.YOURNAME.workers.dev`
8. آدرس را در فیلد **آدرس پروکسی** برنامه بگذارید و **ساخت کانفیگ** را بزنید.

### تست سریع Worker

آدرس Worker را در مرورگر باز کنید. چون فقط درخواست `POST` را پردازش می‌کند، ممکن است خطا یا صفحه‌ی خالی ببینید و این عادی است. اگر داخل برنامه کانفیگ ساخته شد، Worker درست کار می‌کند.

### کد Worker

```js
export default {
  async fetch(req) {
    const cors = {
      'Access-Control-Allow-Origin': '*',
      'Access-Control-Allow-Headers': '*',
      'Access-Control-Allow-Methods': 'POST, OPTIONS'
    };
    if (req.method === 'OPTIONS') return new Response(null, { headers: cors });
    const r = await fetch('https://api.cloudflareclient.com/v0a2158/reg', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'User-Agent': 'okhttp/3.12.1',
        'CF-Client-Version': 'a-6.10-2158'
      },
      body: await req.text()
    });
    return new Response(r.body, {
      status: r.status,
      headers: { ...cors, 'Content-Type': 'application/json' }
    });
  }
}
```

> فقط کلید **عمومی** به Worker و Cloudflare ارسال می‌شود. کلید خصوصی در مرورگر می‌ماند.

### نکات

- **محدودیت رایگان:** پلن رایگان Workers روزانه حدود ۱۰۰ هزار درخواست دارد که برای این کار بیش از کافی است.
- **محدود کردن دسترسی (اختیاری):** در کد، مقدار `'Access-Control-Allow-Origin': '*'` را با آدرس صفحه‌ی خودتان عوض کنید (یعنی `'https://amiralidlb93-hash.github.io'`) تا فقط همان صفحه بتواند از Worker استفاده کند.
- **اگر Worker خطا داد:** در صفحه‌ی Worker بخش **Logs** را ببینید. اگر خطای `403` یا `429` از Cloudflare بود، چند دقیقه صبر کنید و دوباره امتحان کنید.
- **نسخه‌ی API:** اگر روزی API تغییر کرد، آدرس `v0a2158` و مقدار `CF-Client-Version` در کد Worker و برنامه باید به‌روز شوند.

## 🧯 عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| پیام «درخواست مستقیم بلاک شد» | Worker بسازید و آدرسش را در فیلد پروکسی بگذارید |
| کانفیگ ساخته شد ولی وصل نشد | حالت Junk را «سبک» کنید، تیک Amnezia 1.5 را بردارید |

| سرعت پایین است | MTU را تغییر دهید یا endpoint دیگری انتخاب کنید |

## 💡 نکته: آی‌پی‌های 188

طبق تجربه‌ی کاربران، آی‌پی‌هایی که با **`188.`** شروع می‌شوند (مثل `188.114.96.x` تا `188.114.99.x`) معمولاً **بهتر وصل می‌شوند** و پایدارترند.

برای بهترین نتیجه:

1. روی **لیست آی‌پی‌ها برای امتحان** بزنید.
2. اول آی‌پی‌هایی را امتحان کنید که با `188.` شروع می‌شوند.
3. اگر وصل نشد، سراغ بقیه‌ی رنج‌ها (`162.159.x`) بروید.

> این موضوع تجربی است و به اپراتور و شبکه‌ی شما بستگی دارد. روی شبکه‌ی همه کار نمی‌کند، پس اگر یک آی‌پی جواب نداد، آی‌پی یا پورت دیگری را امتحان کنید.
